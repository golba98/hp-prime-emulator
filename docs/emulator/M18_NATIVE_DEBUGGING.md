# M18 — Linked Native debugging

Native linked programs can now be debugged in the CLI and IDE using the existing single VM and linker. This increment changes debugger metadata and navigation; it does not change PPL module initialization or variable-linkage semantics.

## Implemented

- `Machine::call_stack_frames()` exposes each original module/revision and span; `globals_for_frame(depth)` inspects the selected owner's file variables plus shared calculator slots. Existing `call_stack()` and `globals()` remain adapters.
- `ppl debug ROOT.ppl --module LEAF=LEAF.ppl` shares the Run/Check dependency loader. `--break LEAF:5` identifies a source module; numeric command-line breakpoints still target the root. Interactive unqualified breakpoints target the stopped module. Listing, backtraces, frame selection, locals/globals and runtime errors use original sources. Existing single-file output tests remain passing.
- IDE debug workers consume the exact immutable open-source catalog used for compilation. Breakpoints include the module/revision; identical line numbers in other modules do not alias. Step into/over/out use the existing VM frame depth, and explicit breakpoints can interrupt step-over in a dependency.
- Pauses activate the correct source tab and line. Call-stack selection navigates to the selected frame; its private variables remain distinct from identically named caller variables. Only the actual paused tab displays the execution marker.
- Editing or closing a running source opens a captured read-only source tab instead of drawing old locations on changed text. Captured tabs are excluded from linking, cannot be executed or saved over the original, and retain scoped breakpoint controls. They can be selected/copied and closed; they are not persistent source files.
- Dependency initializers are observable by the debugger when they execute. Retained initialized modules remain initialized according to the existing session policy.
- An actual GUI run exposed a previous resume race: Step/Continue left the preceding pause published until the worker consumed the command. Resume now invalidates the old pause while holding the command mutex before publishing the command. This prevents an immediate UI pause query from reporting the previous statement as completion of the requested step. A deterministic bridge regression covers the ordering.
- `PPL_IDE_NO_DEVICE=1` disables IDE USB enumeration and device-job admission. This optional offline mode is used by the native GUI test; ordinary interactive defaults are unchanged. Unit tests retain their unconditional physical-device-open refusal.

## Firmware-controlled Native fidelity increment

A separate disposable HLE session established legitimate exported cross-module variables: an independently installed producer initializes an exported scalar/list/matrix; a consumer reads and mutates the actual owner slots, and the producer observes the changes. Native compilation now retains exported versus private global metadata and unresolved external-variable metadata. Linking follows variable dependencies and relocates scalar reads/writes and indexed writes to the original owner's slot; it never makes all file variables global. Retained owner state follows its exact source revision. Missing/private and ambiguous names fail explicitly. Standalone unlinked references return Undefined instead of a zero value. A fresh low-level linked read initializes its owner, and unverified cross-module variable-initializer cycles return actionable Unsupported.

Actual firmware observations also establish ASCII `i` as a fallback imaginary constant: bare `i` returns complex (0,1); a declared local i returns 7; a declared private function i is callable both explicitly and as a zero-argument bare function and returns 6. Capital I remains a separate calculator variable. Native now resolves ordinary variable/function names before the ASCII imaginary fallback. This preserves local loop variables and function calls.

The shared M18 scenarios pass 43 genuine retained Native/HLE assertions: 14 ASCII imaginary comparisons and 29 exported scalar/list/matrix/state comparisons. The latter includes repeat execution and independent scalar/list-cell/matrix-cell projections (12,9,8). CI runs the same fixtures with Native without proprietary resources or hardware. Exact source identities, helper/firmware hashes, controls and failure classifications are recorded in `evidence/m18/native-fidelity-controls.json`. After integration of the fidelity changes, all 350 tests across ppl-compiler/ppl-vm/ppl-compat passed, as did 19 release codec/representation tests; all-target scoped Clippy with warnings denied and formatting passed.

The first frozen-M17 HLE comparison honestly failed on the fourth retained structured return: firmware completed the call, but its returned list used tag0x16/subtype2, which the codec did not understand. It remained Unobserved rather than passing as an empty value. A rebuilt M18 release helper now captures and decodes only this additionally observed pointer-table subtype using the existing allocation, child-pointer, nesting, item and byte guards. The retained real 156-byte/six-node graph matches independent firmware scalar/index projections. Positive replay, corrupt table/pointer/subtype controls and a known-allocation-neighbor rejection regression cover it. Other unknown subtypes remain Unsupported; no interpretation of the subtype's internal flag meaning is claimed.

## Explicit remaining limits

Firmware rejected `i` as a header parameter and file-level LOCAL variable while Native still accepts these declarations; assigning an undeclared i is a firmware runtime type error but Native rejects it during checking. Those validation-stage/context differences remain explicit. A private-shadow direct Run control failed catalog-order verification in the frozen helper, so that control is infrastructure evidence, not a claim about firmware shadowing. Native private-slot shadowing and dependency-edit invalidation are unit tested but not promoted to new firmware verification here.

Firmware allowed installation of duplicate exported globals and a previously compiled producer retained its old value. Complete duplicate-name rebinding semantics remain unverified; Native refuses ambiguous external variable resolution. Initialization failure/retry and function-initialization-cycle equivalence remain unverified. Dynamic replacement during an active linked call remains Unsupported. No special/nonfinite or otherwise unknown firmware representations were invented. No new physical observations or writes occurred. Native debugging remains separate from firmware CPU debugging and FullSystem diagnostics.
